# S34 — Covert questionnaire to character profile

## When to use

- Use it when a character, persona, brand voice, or user profile has to be built from what the person is actually like, not from what they would pick off a menu.

- Use it when the subject would steer their own answers if they could see where a question was heading.

- Do not use it when the user just wants to pick from finished options; this method builds from a pattern, not from a catalogue.

## Ask one question at a time

- Ask exactly one question per turn, labelled `q. N-` with the running number.

- Never batch questions and never offer batches of finished options to choose from.

- Wait for the answer before asking the next question.

## Keep the questions covert

- Write each question so its steering purpose is not obvious; the subject answers the scenario, not the trait being measured.

- Make questions scenario-based: put the subject in a concrete situation and ask what they do, not what they are.

- Never show your decoding as you go; do not explain what an answer means or what it is building toward.

## Pin the question down

- Build "pinned down" constraints into each scenario that close the loopholes a subject could slip through.

- When the subject finds a loophole in a question, re-ask the same question with that loophole closed.

- Keep re-asking until the answer is a real choice, not an escape hatch.

## Allow passes

- Accept "I don't want to answer that" as a pass; log it as a pass and move on.

- Never ask why they passed and never press for the answer later.

- A pass is data about a boundary, not a failed question.

## Log every answer as it comes

- Write every answer to a profile file as it arrives, with its question number, before asking the next question.

- Use the [questionnaire log](templates/questionnaire-log.md): one entry per question, answer or PASS, with any loophole found and re-ask noted.

- Keep the log in one file so the whole pattern is visible at the end.

- Never rely on chat history alone; the file is the record.

## Build the character at the end, from the whole pattern

- Build only when the questionnaire is closed; build from the whole pattern of answers at once, not from any single answer.

- Produce a profile document first, then a visual build from that profile.

- Never show half-built interpretations mid-questionnaire; the reveal happens at the end.

## Activation loop: preview, confirm, activate, revert

- Show a preview of the visual build and wait for the subject's verdict before activating anything.

- Activate only on an explicit yes.

- If the subject rejects it after activation, revert immediately and ask what specifically is wrong before reworking anything.

## Standing rules

- One item at a time: one question per turn, one build at the end, no parallel versions.

- When the subject rejects a result without naming what is wrong, ask what specifically is wrong before changing anything.

- Never claim more than was checked; the profile is only as good as the answers logged.

## Where this comes from

- Proven end to end in the Arlo character questionnaire: 45 questions, closed 2026-11-06. Rules file from that run: `QUESTIONNAIRE.md` in the character-profile goal files — recorded in the BNB audit as S34.
