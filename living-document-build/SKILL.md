# Living-document build with multi-pass audits

## When to use this skill

- Use it when a guide, manual, or reference document will live and grow over many sessions and must stay correct as a whole.

- Use it when the user is dictating facts and corrections over time and the document must absorb them without drifting into contradiction.

- Do not use it for a one-off write-up; a single-pass draft does not need the audit trio below.

## Build one master document

- Keep one master document as the single source of truth, with numbered sections, stored as a file.

- Update the document in place; never re-write the whole document in chat.

- When the user asks what the document says, answer from the file, not from memory of an older version.

## Fold corrections into the right sections

- When the user corrects a fact, fold the correction into the section it belongs in instead of pasting their words verbatim.

- Check the neighbouring sections for the same fact and update them too, so one correction does not leave a contradiction elsewhere.

- Keep the user's ground truth authoritative over anything research tracks said; when they conflict, the user's version wins and the conflict is noted.

## Audit 1: consistency audit

- Read the whole document looking only for contradictions across sections: numbers, names, procedures, and rules that disagree with each other.

- List every contradiction found with the section numbers on both sides, then fix them in the document.

- Re-read the fixed sections to confirm the fix did not introduce a new contradiction.

## Audit 2: gap audit

- Read the whole document looking only for missing content: steps a procedure skips, gear a section assumes without naming, questions the document raises but never answers.

- List every gap found with the section it belongs in, then fill the gaps in the document.

- When a gap cannot be filled from what is known, mark it as an open question in the document instead of guessing.

## Audit 3: "live the guide" scenario-simulation audit

- Walk through real days and scenarios hour by hour using only what the document says, as if you were living by it.

- Use at least one ordinary day, one hard week, and one worst-case event as scenarios.

- At each hour, trace every procedure the scenario calls for and note any gear, supply, or step it silently assumes but the document never names.

- Fold every finding back into the document as a fix, a new section, or a named open question.

## Standing rules

- Check the user's stated constraints before drafting or recommending anything; a document that contradicts a hard constraint is wrong no matter how thorough it is.

- Never claim more than was checked; audit findings are findings, not fixes, until they are folded into the document.

- The user's real-world verdict closes a fix, not the audit pass.
