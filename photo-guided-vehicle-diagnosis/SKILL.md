# S44 — Photo-guided vehicle electrical diagnosis

## When to use

- Use it when a vehicle (or an appliance with a fuse box) has an electrical fault and the user can send photos.

- Use it when the user is at the vehicle with tools in hand and needs the next test, not a lecture.

- Do not use it to guess a part from the symptom alone; the method narrows to one part by testing.

## Start from the symptom and the photos

- Get the vehicle year, make, and model, plus the symptom in the user's words.

- Ask for photos of the fuse box or boxes: the lid map if there is one, and the fuses themselves.

- Open a [diagnosis worksheet](templates/diagnosis-worksheet.md) for the vehicle and fill it in as you go.

- Work from what the photos actually show; do not assume a layout from a different year or trim.

## Read the fuse map off the photo

- Read the fuse map from the photo of the lid or the owner's diagram the user sends.

- Name the fuse or fuses that feed the failed circuit, with their numbers and ratings from the map.

- When the map is unreadable in the photo, say so and ask for a closer shot instead of guessing.

## Name components by photo landmarks

- Name each component by what the user can see in their photo: color, size, and position, such as "big orange 40A, top row far left".

- Never name a part by a diagram position the user cannot match to their photo.

- Confirm the user has found the right part before moving to the next test.

## Run ordered elimination tests

- Test in order: fuses first, then relay swap, then switch.

- Give one test at a time with the exact steps and what a pass or fail looks like.

- Move to the next test only when the current test's result is known; do not stack tests.

## Use split-branch symptom questions to narrow

- Ask split-branch questions that divide the fault in two: which related circuits still work and which do not.

- Each answer rules out a whole branch; keep asking until one part remains.

- Record the answers as you go so the narrowing is visible and re-checkable.

## Record the actual fix for next time

- When the fault is found, record the actual fix: the part, its location, and what the test showed.

- File the fix with the vehicle and the symptom so the next same-symptom fault starts from the answer.

- Report the fix plainly: what was wrong, what fixed it, and what it cost, if the user says.

## Standing rules

- Never claim more than was checked; a fuse that was not tested is not a fuse that is good.

- One test at a time; the user is at the vehicle, and a batch of tests is a dropped wrench.

- Hard $0 for the diagnosis; parts are the user's call, and the cheapest test comes first.
