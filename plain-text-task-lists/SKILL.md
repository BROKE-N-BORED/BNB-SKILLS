# S87 - Plain-text task lists: numbered, highest to lowest, plain English, no file to open

A task list for him is a numbered list in plain text, highest to
lowest priority, in plain English he can read without opening a
file. No .md document, no metadata, no confusing format. Each item
says what the task is, what it is for, and what it fixes or solves.
The status is labeled, so he never has to guess whether the list is
done or not started.

## When to use

- Use this skill whenever a task list goes to him: after an audit,
  after a review, after a merge, whenever he asks for the list.
- Use it for the list itself, not for the work behind it: the
  merge that builds the list is
  [audit-findings-task-list-merge](../audit-findings-task-list-merge/SKILL.md);
  this skill governs how the list is presented to him.
- Do NOT use it to hide detail he asked for: plain text is the
  format, not an excuse to leave out what each task fixes. If an
  item needs more words to be understood, it gets more words.

## The shape: numbered, highest to lowest, plain English

- Numbered, in order from highest to lowest priority. The number
  is the order: item 1 is the most important thing, and the list
  reads down from there.
- Plain text, in the chat. No .md file to open, no metadata, no
  front matter, no formatting he has to decode. If the list lives
  in a file for the record, the copy he reads is still plain
  text in the chat.
- Plain English, easy to understand. No jargon, no shorthand he
  has not seen, no compressed phrasing that saves words at the
  cost of sense.

## Every item says three things

- What the task is: the work, in plain words.
- What it is for: the purpose, in plain words.
- What it fixes or solves: the problem it answers, or what it
  enhances, in plain words.
- An item missing any of the three is not ready to show him. "Fix
  the crash" with no purpose and no fix named is a note to
  yourself, not a list item for him.

## Label the status, or he will misread it

- Say plainly what state the list is in: none started yet, in
  progress, or complete. A list with no status label reads as
  done, and he will ask whether the items are the ones that are
  complete.
- When the status changes, say so with the list: the list he saw
  yesterday at "none started yet" is a different list today at
  "12 done, 5 to go", and the label is what tells him that.
- Never present a list of work to do in a form that looks like a
  list of work done. The two are opposites, and the label is the
  only thing separating them.

## Status updates are plain English too

- The plain-language rule extends from task lists to status
  updates: a status update must be readable in plain English,
  no jargon, no unexplained numbers.
- Joshua asked for the OST v21 update in plain English; the
  re-sent plain-English version earned a 🙏. The version with
  jargon and unexplained numbers did not land; the plain one
  did.
