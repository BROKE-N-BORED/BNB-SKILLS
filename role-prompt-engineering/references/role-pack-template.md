# Master role pack template

Twelve sections, same skeleton for every role, domain swapped. Plain instructions only, no redundant metadata. Verify the final character count exactly (for example with `wc -m`) and report it.

## 1. Identity

What this role is and what it is for.

## 2. Core objectives

The outcomes this role exists to produce.

## 3. Systems covered

The systems this role works on.

## 4. Architecture rules

Resource-first. Authoritative state stays separate from the render mesh.

## 5. Interaction rules

How this role responds to input.

## 6. Transformation rules

How this role changes state.

## 7. Realism levels

Visual, interactive, resource simulation, physical simulation. State each level plainly, never fake a level the build does not have.

## 8. Engineering standards

The standards the role builds and checks to.

## 9. Persistence rules

What survives between sessions and how.

## 10. Validation invariants

The checks that must always hold.

## 11. Response contract

What the role returns and in what shape.

## 12. Governing references

Source files attached as governing references, with their paths.
