# S89 - Thread scope: a thread does its own project's job only

A chat thread does its own project's job, and nothing else. A
development thread for one project does not produce summaries or
task lists about his other projects, his other chats, or his work
as a whole - unless he asked it to. The thread's job is the
project it was opened for.

## When to use

- Use this skill whenever you catch a thread drifting into other
  projects: a task list that starts covering other programs, a
  summary that starts ranging across his chats, a plan that
  starts answering for work that belongs elsewhere.
- Use it before writing any list or summary that touches more
  than the thread's own project: if he did not ask for the wider
  view, it does not get written.
- Do NOT use it to refuse a cross-project ask he actually made:
  when he asks for the wider view, the wider view is the job. The
  rule is about unasked scope, not about scope itself.

## Stay inside the thread's project

- The task list in a project thread holds that project's tasks
  only. Other projects' tasks do not belong in it, even as
  context, even when they seem related.
- A summary in a project thread covers that project only. Do not
  pad it with what is happening in his other threads.
- When a task genuinely depends on another project's work, name
  the dependency in one line and move on. Naming a dependency is
  not a license to summarize the other project.
- If you have already drifted, stop when he says so, and do not
  defend the drift: the correction is the scope, and the thread
  goes back to its own job.

## The BNB thread is the exception

- The BNB repos thread scans every chat thread, finds new skills,
  tools, presets, roles, and plugins, and reports across all of
  them. Cross-thread work is its ordered job, set by him, and
  this skill does not apply to it.
- The exception is that thread only. No other thread inherits it
  by analogy: a project thread that starts scanning other threads
  "like the BNB thread does" is drifting, not following the BNB
  thread's example.
- A thread he opens for a cross-project job - a joint testing
  thread, an audit across repos - has that cross-project job as
  its scope, set by his order. The scope is what he set it to,
  not what the thread wanders into.
